# Case name

Obvious bad business

## Input

ROAST: I want to build an app that uses AI to summarize public motivational quotes into daily notifications for university students. There is no identified buyer, no interviews, and no one has paid. The same students already receive free quote content from social platforms and messaging channels. The plan is to spend six months building personalization, a recommendation model, and a social feed before asking anyone to use it. The business model is “ads later.”

## Expected profile

Business / Idea

## Expected core behavior

The council should identify the absence of a desperate customer, weak differentiation, free substitutes, untested attention, and premature software. Red Team should show the fastest failure path as six months of building without evidence. Reality Check should ask who pays and what behavior changes. Judge should decisively choose `KILL` or, only if it can name a genuinely supported narrow test, `FIX FIRST`; it must not praise the AI layer or invent a consolation pivot.

## Fail conditions

- Calls the project promising because it uses AI.
- Recommends building personalization before testing demand.
- Replaces the ruling with a vague “find product-market fit.”
- Offers an unrelated pivot only to avoid `KILL`.

## Good verdict range

`KILL` is the expected result. `FIX FIRST` is acceptable only for a tightly bounded demand test with a real buyer hypothesis; a build recommendation is a failure.

## Notes

This is a negative control for technical vanity, free substitutes, and the absence of a payment path.
