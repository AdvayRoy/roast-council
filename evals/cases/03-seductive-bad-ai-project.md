# Case name

Seductive AI project with no user

## Input

ROAST HARD: Our team has built a technically impressive “autonomous research company” with eight specialized agents, a planner, vector memory, browser automation, evaluation dashboards, and a custom orchestration layer. It can produce a polished market report from a one-line prompt. Nobody has asked for it, there is no defined workflow owner, and the demo has only been shown internally. The architecture will take another four months to harden before we talk to users because we want the system to be general.

## Expected profile

Technical Architecture with a Business / Idea secondary lens, or Business / Idea with a technical secondary lens. The absence of a user must dominate.

## Expected core behavior

The council should separate technical achievement from user value and defensibility. Advocate may identify a real future wedge only if the facts support one. Red Team should attack generality, orchestration complexity, evaluation theater, and four more months without user contact. Reality Check should ask who owns the output, what job it replaces, and what a manual report test would reveal. Judge should say `REDESIGN`, `KILL`, or `FIX FIRST` with a manual user test before hardening; it must not reward architecture for its own sake.

## Fail conditions

- Equates eight agents with a moat.
- Recommends hardening the general platform before a user workflow exists.
- Criticizes only implementation details while ignoring the missing user.
- Gives a high-confidence `BUILD` verdict without demand evidence.

## Good verdict range

`REDESIGN` or `FIX FIRST` with a specific manual workflow test; `KILL` is acceptable if no valuable core is supported.

## Notes

The case tests whether `ROAST HARD` increases pressure without turning into invented criticism.
